# Platform concepts

This page explains the resource model behind Ori Developer. It distinguishes the current implementation from the intended product model.

## Workspace

A workspace is the authenticated developer's area in Ori Developer. Clerk provides the signed-in identity. At the current implementation stage, the Projects API associates each project directly with that Clerk user ID.

A full organization/team workspace and shared membership/roles are not implemented yet.

## Project

A project represents an application or integration being built with Ori. Projects are the first persistent resource in the platform.

Currently implemented project fields:

| Field | Meaning |
|---|---|
| \`id\` | UUID generated by Postgres |
| \`name\` | Display name, 2–60 characters |
| \`slug\` | Server-generated URL-friendly identifier, unique per owner |
| \`description\` | Optional description, up to 240 characters |
| \`createdAt\` | Creation timestamp returned by the API |

Every project has an \`owner_id\` set from the authenticated Clerk user on the server. The client cannot select or override the owner.

Project environments, memberships, project-scoped API keys, and project settings are not implemented yet.

## Environments

The intended model separates Development, Preview/Staging, and Production configuration. This separation is a design requirement, not a currently implemented per-project environment manager.

Do not reuse production credentials in local development or preview deployments.

## Credentials

An Ori API credential service is not available yet. The future design distinguishes:

- Personal development credentials owned by a human developer.
- Service identities and credentials owned by an application or automation workload.
- Administrative credentials for tightly controlled platform-management operations.

These credential types must not be treated as interchangeable. See [Authentication and security](AUTHENTICATION.md).

## Models and tools

The Models and Tools sections are currently informational. No live model inventory, inference endpoint, tool registry, or tool execution endpoint is exposed by this repository. See [Models and tools](MODELS_AND_TOOLS.md).

## Activity and usage

A durable audit-event pipeline, request telemetry, and provider-reported usage analytics are not connected yet. The interface must not display fabricated activity or usage totals.
